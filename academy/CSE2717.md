## 定义<img src="./icons/paypal.gif" /><img src="./icons/citic.gif" />

单元测试(unit testing)指对软件中的最小可测试单元进行检查和验证。

https://en.wikipedia.org/wiki/Unit_testing

*In object-oriented programming, a unit is often an entire interface, such as a class, or an individual method. By writing tests first for the smallest testable units, then the compound behaviors between those, one can build up comprehensive tests for complex applications.*

## 为什么要使用Mock进行单元测试？<img src="./icons/paypal.gif" /><img src="./icons/citic.gif" />

我们时常会遇到由于依赖组件无法工作而造成的测试阻碍，例如：

- 远程通信
- 文件操作
- 对象复杂，难以初始化
- 抛出异常的场景

以上问题可能会导致不少单测案例难以通过，影响单测覆盖率。

而Test Double就是规避这个风险的手段。在测试过程中，我们有时可以使用Test Double替代真实的依赖组件去和待测系统进行交互。Test Double不必和真实的依赖组件的实现一模一样，比如不用去实现依赖组件复杂的内部逻辑等，我们只需要在满足测试需求范围内，确保对于待测系统来说Test Double提供的API是和依赖组件提供的一样的，而API在内部实际上是怎么实现的这种和本次单测无关的内容，就可以无需关注了。

| Isolate System Under Test (SUT) from its dependencies | →    | Inject behavior | →    | Verify expectations |
| ----------------------------------------------------- | ---- | --------------- | ---- | ------------------- |

### Mockito

Mockito是一个针对Java的Mocking框架。可以通过简单的方法Mock对象的类库，避免了手工编写Mock对象。

它与EasyMock和JMock很相似，但是Mockito比较简洁。

### PowerMock

PowerMock一般与Mockito搭配使用，PowerMock基本上覆盖了所有Mockito不能支持的情况，可以用来弥补Mockito在功能上的不足。

> **Legacy 提示**：PowerMock 最后版本为 2.0.9（2020 年），项目已冻结——仅支持 JUnit 4，仅适配 Mockito 2.x。现代项目（JUnit 5 + Mockito 5）中，Mockito 自 3.4.0 起通过 inline mock maker（Mockito 5 起为默认）原生支持 static 与 final 方法的 mocking，`mockito-junit-jupiter` 提供 `@ExtendWith(MockitoExtension.class)`，新代码不再需要 PowerMock。本节内容仍适用于维护存量 JUnit 4 + PowerMock 代码库。

## 步骤<img src="./icons/paypal.gif" />

| **Initialization**                                           | **Mocking**                                                  | **Invoking**                           | **Verification**                                             |
| ------------------------------------------------------------ | ------------------------------------------------------------ | -------------------------------------- | ------------------------------------------------------------ |
| Prepare required objects                                     | Inject specific  properties                                  | Invoke tested method                   | Verify whether we have  the result same as the expectation   |
| *Define  a Kosaka(Singer of PPAP) who has  one apple, one pineapple, and two pens.* | *Allow  apple and pen to be combined as an apple-pen.*  *Allow  pineapple and pen to be combined as a pineapple-pen.*  *Allow apple-pen  and pineapple-pen to be combined as a PPAP.* | *Let your specific Kosaka  sing PPAP.* | *Check  whether your Kosaka's final result is identical to your pre-defined PPAP.*  *Check  whether your Kosaka has done the action of combining three times.* |

### Initialization

#### 命名<img src="./icons/alibaba.gif" />

|               | **Class name**  | **File path**         | **Method name**                                              |
| ------------- | --------------- | --------------------- | ------------------------------------------------------------ |
| Tested Class  | {ClassName}     | src/{Identical Part}  | {MethodName}                                                 |
| Testing Class | {ClassName}Test | test/{Identical Part} | test{MethodName} or test{MethodName}{Special condition of this method} |

示例如下：

```java
//被测试类
public class Calculator {
    private Button[] buttons;
    public Calculator() {
        //...
    }
    public void push(int index) {
        //...
    }
}
class Button {}

//测试类
@RunWith(PowerMockRunner.class)
@PrepareForTest({})
public class CalculatorTest {
	@Test
	public void testPushValidButton() {
        //...
    }
	@Test
	public void testPushInvalidButton() {
        //...
    }
}
```

注：`test` 前缀是 JUnit 3 时代的要求；JUnit 4/5 中 `@Test` 注解已使方法名前缀非必需，现代风格直接使用方法名（可带预期结果与场景，如 `pushInvalidButton`）。

#### 引入依赖

为了引入Mockito和PowerMock包，需要在maven项目的pom.xml文件中加入以下包依赖。

在PowerMock包中，已经包含了对应的Mockito和JUnit包，所以无需单独引入Mockito和JUnit包。

```xml
<dependency>
    <groupId>org.powermock</groupId>
    <artifactId>powermock-core</artifactId>
    <version>${powermock.version}</version>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.powermock</groupId>
    <artifactId>powermock-api-mockito2</artifactId>
    <version>${powermock.version}</version>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.powermock</groupId>
    <artifactId>powermock-module-junit4</artifactId>
    <version>${powermock.version}</version>
    <scope>test</scope>
</dependency>
```

现代项目（JUnit 5 + Mockito 5，无需 PowerMock）的最小依赖：

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>${junit-jupiter.version}</version>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.mockito</groupId>
    <artifactId>mockito-junit-jupiter</artifactId>
    <version>${mockito.version}</version>
    <scope>test</scope>
</dependency>
```

Mockito 5 默认启用 inline mock maker，可直接 `Mockito.mockStatic(...)`、`mockConstruction(...)` 及 mock final 类/方法，API 与本文 PowerMock 对应能力基本一致。

#### 定义对象

这个阶段分为以下三步：

- 定义被测对象（new或spy）
- 定义依赖对象（new, mock或spy）
- 注入依赖对象

如果需要新建一个被测试类的实例，可以采取以下三种方法：

```java
//对于一些参数不多，逻辑不复杂的测试对象，可以不使用PowerMock框架，直接new一个新实例用于测试。
Obj obj = new Obj();
obj.setName("NAME");
//mock出的对象可以自行定义特定函数的返回值、跳过逻辑执行。未定义的函数不执行任何逻辑、返回值为空。
Obj obj = PowerMockito.mock(Obj.class);
PowerMockito.when(obj.getName()).thenReturn("NAME");
PowerMockito.when(obj, "getNameMethod").thenCallRealMethod();
//spy出的对象可以自行定义特定函数的返回值、跳过逻辑执行。未定义的函数执行函数原有逻辑、返回值不一定为空。
Obj obj = PowerMockito.spy(new Obj());
PowerMockito.doReturn("NAME").when(obj).getName();
```

### Mocking

#### 设置属性

```java
//用传统反射方式设置私有变量
PrivateObject instance = new PrivateObject();
Field instanceField = TestedClass.class.getDeclaredField("privateObject");
instanceField.setAccessible(true);
instanceField.set(testedClass, instance);
//用PowerMock自带的MemberModifier设置私有变量
PrivateObject instance = new PrivateObject();
MemberModifier.field(PrivateObject.class, "privateString").set(instance, "WHATEVER");
//用PowerMock自带的Whitebox设置私有变量（Whitebox 属于 PowerMock 的 org.powermock.reflect 包，不是 Mockito 的 API）
Whitebox.setInternalState(object, "fieldName", value);//可以设置某个对象的某个field。
Whitebox.getInternalState(object, "fieldName");//获取某个对象的某个field的值。
Whitebox.invokeMethod(object, methodName, para);//可以调用私有方法，测试私有方法的返回值。
```

#### 设置触发条件 when()

*模拟被测试类中某个成员对象调用其自身方法时，可以采用如下方式：*

```java
Obj obj = PowerMockito.mock(Obj.class);
//使用指定参数的when方法
Input input = Input.getInstance();
String str = "STRING";
PowerMockito.when(obj.getOutput(input, str)).thenReturn(true);
//使用指定参数类型的when方法
//注意：参数为 null 时不匹配 anyString()/any(Class)（Mockito 2 起 any(Class) 排除 null），不会被桩代码拦截；
//需要匹配 null 时使用 Mockito.isNull() 或 nullable()（无参的 any() 则匹配 null）。
PowerMockito.when(obj.getOutput(Mockito.any(Input.class), Mockito.anyString())).thenReturn(true);
```

#### 设置触发条件 whenNew()

*模拟被测试类中创建新成员对象时，调用这个方法。*

```java
//如果某个类A内部的new 类B被whenNew调用，请在@PrepareForTest注解中加入类A.class
Obj obj = PowerMockito.mock(Obj.class);
//使用指定参数的whenNew方法
Input input = Input.getInstance();
String str = "STRING";
PowerMockito.whenNew(Obj.class).withArguments(input, str).thenReturn(obj);
//使用不指定参数的whenNew方法
PowerMockito.whenNew(Obj.class).withAnyArguments().thenReturn(obj);
//使用指定无参数的whenNew方法
PowerMockito.whenNew(Obj.class).withNoArguments().thenReturn(obj);
```

#### 设置响应结果

```java
Obj obj = PowerMockito.mock(Obj.class);
Input input = Input.getInstance();
String str = "STRING";
//设置指定返回值
PowerMockito.when(obj.getOutput(input, str)).thenReturn(true);
//设置指定返回值（另一种写法，避免 when() 中内联调用真实方法产生的副作用）
Mockito.doReturn(true).when(obj).getOutput(input, str);
//设置指定抛出异常
PowerMockito.when(obj.getOutput(input, str)).thenThrow(new RuntimeException());
//设置指定抛出异常（注意用 doThrow 而不是 doReturn——doReturn 会把异常对象当作返回值，不会抛出）
Mockito.doThrow(new RuntimeException()).when(obj).getOutput(input, str);
//设置无返回值（用于 void 方法）
Mockito.doNothing().when(obj).getOutput(input, str);
```

#### 模拟final方法

```java
@RunWith(PowerMockRunner.class)
@PrepareForTest({FinalMethodClass.class})
//...
FinalMethodClass finalMethodClass = PowerMockito.mock(FinalMethodClass.class);
//...
```

#### 模拟private方法

```java
@RunWith(PowerMockRunner.class)
@PrepareForTest({PrivateObject.class})
//...
PrivateObject instance = new PrivateObject();
MemberModifier.stub(MemberModifier.method(PrivateObject.class, "privateString")).toReturn("WHATEVER");
//...
```

#### 模拟static方法

```java
@RunWith(PowerMockRunner.class)
@PrepareForTest({StaticMethodClass.class})
//...
PowerMockito.mockStatic(StaticMethodClass.class);
//mockStatic 之后直接对静态方法打桩与验证，不要再 mock 该类的实例：
PowerMockito.when(StaticMethodClass.staticMethod()).thenReturn(expectedValue);
//...
```

### Invoking

```java
//直接调用
boolean result = obj.getOutput();
//通过反射调用
Method getOutput = Obj.class.getDeclaredMethod("getOutput");
getOutput.setAccessible(true);
boolean result = getOutput.invoke(obj);
//通过Whitebox调用（第三个参数起为方法实参，按被测方法的参数类型传入）
String output = Whitebox.invokeMethod(obj, "getOutput", "someString");
```

### Verification

```java
//State Verification
int expected = 2;
int actual = 1 + 1;
//JUnit方法，验证两个对象是否相等
Assert.assertEquals(expected, actual);
//JUnit方法，验证boolean值是否为true
Assert.assertTrue(expected == actual); 

//Behavior Verification
//被调用了1次
Mockito.verify(obj, Mockito.times(1)).getOutput();
//没有被调用过
Mockito.verify(obj, Mockito.never()).getOutput();
//验证Static类的静态方法thirdStaticMethod(Int)被调用了3次
PowerMockito.verifyStatic(Static.class, Mockito.times(3));
Static.thirdStaticMethod(Mockito.anyInt());
```

## Code Coverage<img src="./icons/paypal.gif" />

**Line Coverage**

Display how many lines have been tested. Even if there are many separated branches missed, the result might not be dramatically affected.

**Branch Coverage**

Display how many branches have been tested. If the code contains no condition or loop, there are no branches to miss and the result is trivially 100%.

**Method Coverage**

Display how many methods have been invoked by tests. A method counts as covered once called, regardless of which branches inside it were hit — so 100% method coverage can still coexist with very low branch coverage.

**On Local IDEA**

Click Run 'All Tests' with Coverage or Run 'xxxTest' with Coverage. If there is no option, try to find it under More Run/Debug.

**With JaCoCo (CI)**

IDEA 之外，CI 流水线通常使用 JaCoCo（Maven/Gradle 插件）生成 Line/Branch/Method 覆盖率报告，并常与构建门禁（如 line coverage ≥ 80%）绑定；本地也可用 `mvn jacoco:report` 在 `target/site/jacoco` 查看 HTML 报告。
