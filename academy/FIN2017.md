## 五个术语

| 术语 | 是什么 |
| --- | --- |
| PAN | 主账号，通常就是卡号 |
| CVV/CVC | 卡上三位或四位安全码，常用于网上交易验证 |
| PIN | 卡密码，和 CVV 不是同一个东西 |
| Token 化 | 用替代标识代表真实卡信息，减少真实卡号在系统间传播 |
| 3DS | 网上卡支付的持卡人身份验证机制，有时会要求验证码或 App 确认 |

## Token 是不是把卡号加密了

不完全一样。**加密**是把原数据转成密文，持密钥可以解密还原；**Token 化**是用替代标识引用真实卡信息，真实数据由受控系统管理。业务系统能用 Token 完成业务，但未必接触得到真实卡号。注意：支付卡的 Token 是替代标识，和数字资产代币不是一个概念。

## 3DS 通过，交易就一定成功吗

不一定。3DS 验证的是"用卡的人是谁"，授权判断的是"这笔交易能不能做"。身份验证通过后，仍可能因为余额不足、限额或风控被拒绝。而且 3DS 不一定每次都弹验证码，验证方式取决于具体流程。

## PCI-DSS 是什么

银行卡数据安全标准。对研发来说，重点是控制卡数据的收集、传输、存储和访问，减少泄露风险。

**CVV 要特别记住**：商户及其服务商通常不能在授权后保存 CVV——即使加密也不行，不能为了订阅扣款留下它。发卡机构及支持发卡的服务商在合法业务需要时存在特定例外，别把商户侧规则机械套到所有发卡场景。

## 你会怎么保护卡信息

- 业务系统尽量用 Token，减少接触完整卡号。
- 确实要处理的数据：加密、限制访问、管理密钥、记录审计。
- 日志、监控、排查数据要脱敏，不能为了排查方便打印完整卡信息。
- 用了第三方服务也不等于不用管 PCI：第三方缩小的是敏感数据接触面，责任不会自动消失。要确认自己处理哪些数据、哪些系统能影响卡数据环境，明确双方职责。

边界话术：没主导过 PCI 认证，就说"熟悉相关工程原则"，不要把"做过安全控制"说成"负责过认证"。

## 本章面试主线

> 五个词认识即可：PAN/CVV/PIN/Token/3DS。Token 是替代标识不是加密，3DS 是人证不是交易批准。工程底线：卡号能 Token 就 Token，CVV 授权后不留存，日志全脱敏，合规责任不随第三方转移。
