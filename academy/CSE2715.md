## slf4j

SLF4J 的全称为 Simple Logging Facade for Java。它为 Java 程序提供统一的日志 API，并不是具体的日志实现；这与 JDBC 只定义统一接口的作用类似。

SLF4J 应与具体的日志实现及其版本匹配的绑定（SLF4J 2.x 中称为 provider）配合使用，例如 Logback，或通过相应绑定接入 Log4j 1.x 和 `java.util.logging`。仅导入 SLF4J API 而没有绑定时，日志不会输出到实际后端。

## log4j

以下内容基于 Log4j 1.x。该版本已停止维护，新项目应使用 Log4j 2 或 Logback。Log4j 1.x 是 Apache 的开源项目，通过它可以控制日志输出的目的地，例如控制台、文件、GUI 组件、套接字服务器、NT 事件记录器和 UNIX Syslog 守护进程；还可以控制每一条日志的输出格式，并通过日志级别细致地控制日志生成过程。

Log4j 由三个重要组成部分构成：

- **日志记录器**（Loggers）控制要启用或禁用哪些日志记录语句，并对日志信息进行级别限制。

- **输出端**（Appenders）指定日志输出到控制台、文件或其他目标。

- **日志格式化器**（Layout）控制日志信息的显示格式。

Log4j 1.x 定义了 5 种日志级别：DEBUG、INFO、WARN、ERROR 和 FATAL，严重程度依次升高。输出时，级别**不低于**（`>=`）配置级别的信息才会被记录；例如配置为 INFO 时，INFO、WARN、ERROR 和 FATAL 都会输出。这样可以针对不同环境调整输出内容，而不需要更改代码。

Log4j 2 的级别与此不同：除上述常用级别外，还包括 TRACE，以及用于配置的 ALL 和 OFF。

## logback

Logback 是 Java 领域的日志框架，由 Log4j 的创始人开发，其设计受到 Log4j 的影响。

Logback 主要由三个模块组成：

- **logback-core** 提供关键通用机制的基础设施，其他模块基于它构建。

- **logback-classic** 提供完整的日志实现，并实现 SLF4J API，使应用可以通过 SLF4J 将日志输出到 Logback。

- **logback-access** 用于与 Tomcat、Jetty 等 Servlet 容器交互，提供与 HTTP 访问相关的功能。
