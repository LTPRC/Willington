> **本章定位：**Immutability。回答高频面试题：**"区块链的数据为什么改不了？"**主线：哈希函数性质 → 链式结构放大改动 → 重算需要压倒性算力（51%）→ 经济上得不偿失。结论的准确表述是"经济安全"，不是"数学绝对"。

## 保证数据不可篡改的机制<img src="./icons/alibaba.gif" />

区块链的区块之间相互链接成为链条，存储很难被篡改的数据，因为每个区块链都保留上一个区块的hash值，而hash值只要有任何改动就变得不一样。如果你要修改一个区块链，那么你需要把这个区块所在链条上所有的区块都修改了。整个链条上不只你一个人，如果你拥有的链条和别人都不一样，那么就不会被接受。当然也有可能被接受，你需要很强大的算力，在修改的区块的下一个区块生成之前运用强大的算力修改内容。反hash值计算特别难，特别浪费时间。这种算力支持需要打败区块链网络上51%的算力才有可能实现。这种做法得不偿失，假设大家都是理性的，那么区块链的数据就是不可篡改的。

> **表述修正：**原文"每个区块链都保留上一个区块的hash值"应为"每个**区块**保留上一个**区块**的hash值"；"修改一个区块链"应为"修改一个**区块**"。按区块（block）理解即可，机制描述本身是对的。

## 哈希函数为什么可信

防篡改的地基是密码学哈希（比特币用 SHA-256）的三个性质：

| 性质 | 含义 | 在区块链里的作用 |
|---|---|---|
| 单向性 | 无法从 hash 反推出原文 | 无法"造一个内容去凑指定哈希" |
| 抗碰撞 | 找不到两个不同输入产生相同 hash | 每个区块指纹唯一 |
| 雪崩效应 | 输入改 1 bit，输出面目全非 | 任何改动立刻暴露 |

> **Senior Java Focus：**量化感受：SHA-256 输出空间 2^256 ≈ 10^77。想找一个满足条件的哈希，唯一办法就是换输入反复试——"难算易验"正是 PoW 挖矿的原理（见 [SYS4113 共识算法](./SYS4113.md)）：找 nonce 难，验证只需算一次哈希。

## 篡改一个块的连锁反应

``` text
改 Block N 里的一笔交易
   ↓
该交易的哈希变 → Merkle Root 变
   ↓
Block Header 变 → Block N 的哈希变
   ↓
Block N+1 的 prevBlockHash 失配 → N+1 必须重算
   ↓
Block N+2 ... 直到链头，全部重算
   ↓
同时，诚实矿工还在正常延长原链
   ↓
你必须以一己之力持续跑赢全网合计算力
```

两个放大器：

1. **结构放大**：改一处 → 重算整条尾巴（哈希难反算，只能暴力重挖）。
2. **竞争放大**：重算期间全网还在往前走。要追上并反超，需要长期掌握全网 **>50% 算力**——这就是 51% 攻击的出处。

## 51% 攻击能做什么、不能做什么

| 能 | 不能 |
|---|---|
| 双花（double spend）：撤销自己已确认的付款，把同一笔钱再花一次 | 凭空增发（受全网节点独立验证的共识规则约束） |
| 审查：拒绝打包某些交易 | 偷别人的币（没有私钥就无法构造合法签名交易） |
| 短程改写最近几个块 | 改写久远历史（重算成本随深度暴涨，不现实） |

> **Senior Java Focus：**"双花"是支付人最关心的词。传统支付里防双花靠银行账户余额的串行扣减 + 防重流水（见 [SYS4015](./SYS4015.md) 幂等/防重）；UTXO 模型下双花表现为"同一个输出被两笔交易引用"，全网节点验证时直接拒绝（详见 [SYS4114](./SYS4114.md)）。

## "不可篡改"的准确表述

- 不是数学绝对，而是**经济安全**：攻击成本 > 攻击收益，且攻击成功会导致链的信用崩塌、币价归零——攻击者自己持有的资产同时蒸发。
- 原文的"假设大家都是理性的"正是这个意思：安全建立在理性经济人假设之上。
- 工程实践对应：**确认数就是风险控制参数**。小额支付 1~3 确认可接受，大额等 6 确认甚至更多——本质是利用"改写概率随深度指数衰减"给自己买保险。

## 本章面试主线

> 哈希性质（单向/抗碰撞/雪崩）→ 链式结构（改一处、重算整条尾巴）→ 51% 门槛（单点算力持续跑赢全网）→ 经济不可行（得不偿失 + 币价崩塌）→ 结论：不可篡改 = 经济安全，确认数 = 风控参数。
