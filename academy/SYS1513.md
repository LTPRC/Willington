## 检查网络连接 - ping命令<img src="./icons/ericsson.gif" /><img src="./icons/mashibing.gif" />

ping可以说是ICMP的最著名的应用，是TCP/IP协议的一部分。利用“ping”命令可以检查网络是否连通，可以很好地帮助我们分析和判定网络故障。

它利用ICMP协议包来侦测另一个主机是否可达。原理是发出类型码为8的ICMP回显请求（Echo Request），收到请求的主机用类型码为0的ICMP回显应答（Echo Reply）回应。

ping程序来计算间隔时间，并计算有多少个包被送达。用户就可以判断网络大致的情况。我们可以看到，ping给出来了传送的时间和TTL的数据。ping 直接使用 ICMP 协议（不依赖 TCP/UDP 端口），如果网络延迟是Xms, ping一个网站至少需要一个round-trip的用时，共计2Xms.

```bash
$ ping github.com
Reply from 192.30.255.113: bytes=32 time=211ms TTL=46
...
Ping statistics for 192.30.255.113:
    Packets: Sent = 4, Received = 4, Lost = 0 (0% loss),
    Minimum = 211ms, Maximum = 212ms, Average = 211ms
```

输出要点：每个 Reply 行给出往返时延 time（ms）与 TTL；末尾统计行看 Lost 丢包率和 Min/Max/Average 延迟。

## 发起请求 - curl命令<img src="./icons/baidu.gif" />

curl 是常用的命令行工具，用来请求 Web 服务器。它的名字就是客户端（client）的 URL 工具的意思。它的功能非常强大，命令行参数多达几十种。如果熟练的话，完全可以取代 Postman 这一类的图形界面工具。

不带任何参数时 curl 就是发出 GET 请求：`curl https://www.example.com`。

**常用参数**

| 参数 | 含义 | 示例值 |
| ---- | ---- | ------ |
| -A | 设置 User-Agent 标头（默认 curl/[version]；也可用 -H 设置） | -A 'Mozilla/5.0 ...'，置空 -A '' 移除 |
| -b | 向服务器发送 Cookie（可直接写或从本地文件读取） | -b 'foo1=bar;foo2=bar2' / -b cookies.txt |
| -c | 将服务器设置的 Cookie 写入文本文件 | -c cookies.txt |
| -d | POST 请求数据体；自动转 POST 方法并加标头 Content-Type: application/x-www-form-urlencoded，可省略 -X POST | -d 'login=emma&password=123' / -d '@data.txt' |
| --data-urlencode | 同 -d，但自动对数据进行 URL 编码 | --data-urlencode 'comment=hello world' |
| -e | 设置 Referer 标头（请求来源），等效于 -H 'Referer: ...' | -e 'https://google.com?q=example' |
| -F | 以 multipart/form-data 上传文件（默认 MIME 为 application/octet-stream，可用 ;type= 指定、;filename= 改名） | -F 'file=@photo.png;type=image/png' |
| -G | 发出 GET 请求，-d 数据作为查询字符串 | -G -d 'q=kitties' -d 'count=20' |
| -H | 添加任意 HTTP 标头，可多次使用 | -H 'Content-Type: application/json' |
| -i | 输出响应标头，空一行后再输出网页源码 | -i |
| -I | 发 HEAD 请求，只打印响应标头（= --head） | -I |
| -k | 跳过 SSL 证书检测 | -k |
| -L | 跟随重定向（curl 默认不跟随） | -L |
| --limit-rate | 限制请求/回应带宽，模拟慢网速 | --limit-rate 200k |
| -o | 将响应保存成文件（等同 wget） | -o example.html |
| -O | 保存响应，以 URL 最后部分作文件名 | -O https://.../bar.html |
| -s | 错误时不显示错误信息；-s -o /dev/null 则完全无输出 | -s |
| -S | 只输出错误信息（常与 -s 搭配） | -S |
| -u | 设置 HTTP 认证用户名密码（转 Authorization: Basic 头）；也可写在 URL 中（user:pass@host），只给用户名会提示输密码 | -u 'bob:12345' |
| -v | 输出通信全过程用于调试（--trace 更详细，含原始二进制数据） | -v |
| -x | 指定代理（不指定协议时默认 HTTP） | -x socks5://james:cats@myproxy.com:8080 |
| -X | 指定 HTTP 请求方法 | -X POST |

**代表例**

```
# 发送 JSON 数据（-d 自动转 POST，-H 加 Content-Type）
$ curl -d '{"login": "emma", "pass": "123"}' -H 'Content-Type: application/json' https://google.com/login

# 上传文件
$ curl -F 'file=@photo.png' https://google.com/profile

# 认证：设置用户名密码（等效于 https://bob:12345@google.com/login）
$ curl -u 'bob:12345' https://google.com/login

# 跟随重定向的 POST
$ curl -L -d 'tweet=hi' https://api.twitter.com/tweet

# 只看响应标头
$ curl -I https://www.example.com
```

## 查看端口被什么程序占用<img src="./icons/apple.gif" /><img src="./icons/baidu.gif" />

### ss命令

ss 一般用于转储套接字统计信息。它还可以显示所有类型的套接字统计信息，包括 PACKET、TCP、UDP、DCCP、RAW、Unix 域等。

输入：

```bash
ss -lntp | grep :22
```

得到：

```bash
tcp LISTEN 0 128 0.0.0.0:22 0.0.0.0:* users:(("sshd",pid=6806,fd=3))
tcp LISTEN 0 128 [::]:22 [::]:* users:(("sshd",pid=6806,fd=4))
```

通过grep来获取到对应的记录， 如果是本身用户可以直接查看到pid信息，如果是其他用户的程序一般使用root权限就可以查看到所有程序的进程信息。

### lsof命令

lsof(list open files)是一个列出系统上被进程打开的文件的相关信息。

输入：

```bash
lsof -i tcp:22
```

得到：

```bash
COMMAND PID USER FD TYPE DEVICE SIZE/OFF NODE NAME
sshd 6806 root 3u IPv4 147399 0t0 TCP *:ssh (LISTEN)
sshd 6806 root 4u IPv6 147401 0t0 TCP *:ssh (LISTEN)
```

同理，要查看到所有程序需要有root权限。

### netstat命令<img src="./icons/mashibing.gif" />

历史命令：`netstat -tnlp | grep :22` 效果与 ss 等同（-t tcp、-l 监听中、-n 端口号、-p 程序名称，看不到名字可在命令前加 sudo）。目前 netstat 已经过时，推荐用 ss 代替。

## 侦测路由情况 - tracert

注：Linux 下对应命令为 traceroute（默认用 UDP 探测），tracert 是 Windows 版本（用 ICMP 探测）。

tracert的原理是非常非常的有意思，它收到目的主机的IP后，首先给目的主机发送一个TTL=1的UDP数据包，而经过的第一个路由器收到这个数据包以后，就自动把TTL减1，而TTL变为0以后，路由器就把这个包给抛弃了，并同时产生一个ICMP超时（Time Exceeded）数据报给主机。主机收到这个数据报以后再发一个TTL=2的UDP数据报给目的主机，然后刺激第二个路由器给主机发ICMP数据报。如此往复直到到达目的主机。这样，tracert就拿到了所有的路由器IP.

```shell
$ tracert www.qq.com
Tracing route to ins-r23tsuuf.ias.tencent-cloud.net [111.30.178.240]
over a maximum of 30 hops:
  1    <1 ms    <1 ms    <1 ms  192.168.0.1
  2     1 ms    <1 ms    <1 ms  SMBSHARE [192.168.1.1]
  ...（每行一跳：TTL 逐次递增，直到到达目的主机或达到 30 跳上限）
```

## iptables<img src="./icons/mashibing.gif" />

netfilter/iptables(简称为iptables)组成Linux平台下的免费的包过滤防火墙。

```bash
service iptables {start/stop/status}
chkconfig iptables {on/off}
```

（现代注记：systemd 发行版中 service/chkconfig 已被 systemctl 取代：`systemctl {start|stop|status} iptables`、`systemctl {enable|disable} iptables`；部分发行版默认防火墙已换为 firewalld。）
