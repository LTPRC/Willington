> **本章定位：**Blockchain vs Bitcoin。原面试材料里成对出现的对比题。主线：**协议 vs 实现**、共识算法差异、交易速度口径、链的形态（公有/联盟/私有）、局限性。比特币关键参数（2100 万、10 分钟、UTXO）作为速查表收尾。

## 本质区别

区块链是一种价值传递的协议；比特币是一个基于密码学的数字货币、区块链的一个初级实现。

三个层次的拆解：

``` text
区块链   = 底层技术与协议（账本结构 + 共识规则 + 激励机制）
比特币   = 建立在协议上的第一个大规模应用（电子现金）
其他应用 = 以太坊（智能合约平台）、联盟链（机构间清算）等
```

- 类比：**区块链之于比特币，如同 TCP/IP 之于 Web**。一个是信任/通信的协议层，一个是跑在协议上的具体应用。
- "初级实现"不等于"差"——比特币是运行时间最长、经受攻击最多的生产级区块链；但它的脚本语言刻意非图灵完备，表达能力有限。

## 算法

区块链既可以用比特币的POW（工作量证明）算法又可以用POS（权益证明）算法，也可以用DPOS算法；比特币的共识算法是POW（工作量证明）算法。

> **纠错说明：**原文写作"DPS算法"，应为 **DPOS（Delegated Proof of Stake，委任权益证明）**。三种算法的机制、对比与选型详见 [SYS4113 共识算法](./SYS4113.md)。

## 交易速度

区块链每秒钟的交易次数可以达到上万次或者更多；比特币每秒钟的交易最大只能有七笔每秒。

> **口径说明：**"上万次"是联盟链/新公链的**理论或实验室口径**，不是公有链实测。引用数字先分类：比特币约 7 TPS（1MB 区块 × 10 分钟决定的物理上限）；以太坊十几到几十 TPS；上千上万 TPS 基本来自联盟链（节点少、共识轻）或分片/新公链的白皮书口径。面试直接说"区块链上万 TPS"而不加限定，容易被追问翻车。

| 系统 | 量级 | 限制来源 |
|---|---|---|
| 比特币 | ~7 TPS | 1MB 区块 × 10 分钟出块 |
| 以太坊 | 十几~几十 TPS | Gas 上限 × 秒级出块 |
| 联盟链（PBFT 类） | 上千（理论可更高） | 节点少、许可制、O(n²) 通信上限 |

> **Senior Java Focus：**吞吐对比接回支付系统常识：Visa 级网络宣称数万 TPS；在线支付对单笔延迟的要求是亚秒级，而公有链出块等待是分钟级——所以区块链在支付领域的现实落点是**清算/对账层**而不是收单层。这句判断比背数字值钱。

## 链接形式：公有链 / 私有链 / 联盟链

区块链可以有公有链、私有链，或者联盟链的形式；比特币基于互联网，是公有链。

| 维度 | 公有链 | 联盟链 | 私有链 |
|---|---|---|---|
| 准入 | 任何人可读写 | 多机构共同运营，成员授权 | 单一机构内部 |
| 信任模型 | 互不信任的陌生人 | 半信任的已知机构 | 基本等于内部系统 |
| 共识 | PoW / PoS | PBFT 类 / Raft 类 | 通常无需拜占庭容错 |
| 典型 | 比特币、以太坊 | Hyperledger Fabric、Corda、Quorum | 企业内部审计账本 |
| 价值 | 去中心化、抗审查 | 多方对账、留痕、监管友好 | 存证/审计场景 |

> **Senior Java Focus：**被问"私有链有什么意义，一家公司自己记账不就行了"——标准答案：私有链真正的买点是**多部门/多子公司之间的留痕与审计**；对单一机构它确实近似一个 append-only 数据库。价值排序：联盟链 > 公有链 > 私有链。

## 比特币关键参数速查

- 总量上限：**2100 万枚**（协议硬编码，约 2140 年挖完）
- 出块间隔：约 10 分钟；每 **2016 块**调整一次难度
- 产出减半：约每四年区块奖励减半
- 吞吐：约 **7 TPS**
- 共识：PoW（SHA-256，块头哈希）
- 交易模型：**UTXO**
- 确认惯例：**6 确认**视为不可逆

### UTXO vs 账户模型

``` text
UTXO（比特币）：
"账" = 全网未花费输出(unspent outputs)集合
花 100 币中的 30 币 → 消耗一个 100 的旧输出
                    → 生成 30 给对方 + 70 找零给自己 两个新输出
像现金：花的是"那张钞票"；双花 = 同一张钞票付两次，全网验证直接拒绝

账户模型（以太坊）：
"账" = address → balance
转账直接加减余额
像银行账户：双花防护依赖交易顺序（nonce）与余额串行校验
```

> **Senior Java Focus：**UTXO 的"未花费输出集合"本质是一个**全局防重表**：每个输出只能被消费一次，第二次引用直接非法——和支付系统里"唯一业务单号 + 防重流水"（见 [SYS4015](./SYS4015.md)）是同一个思想在不同世界的实现。

## 局限性

区块链也有一些局限性，虽然它只是一个协议，是一个技术，但是它还是处于萌芽阶段的一个新技术；比特币并不符合金融监管，也就是说这2100万枚比特币是在没有国家授权的情况下，没有国家信用作为背书的情况下被发行出来的。

> **纠错说明：**原文"没有国家信用作为**倍数**"应为"没有国家信用作为**背书**"。

补充两点常被追问的局限：

- **扩展性三角（scalability trilemma）**：去中心化、安全性、吞吐三者难以兼得——比特币取前两者牺牲吞吐；联盟链取吞吐牺牲去中心化。任何"又快又去中心化又安全"的宣传都按这个框架审视。
- **链上治理与监管**：匿名性、跨境流动、无授权发行（原文点）使其与反洗钱/外汇监管体系天然紧张；联盟链（许可制 + 监管节点）正是面向这个矛盾的工程折中。

## 区块链未来会应用到哪些领域？

区块链未来可能应用到清算结算、股权交易、审计、公证等多个领域。

> 与 SYS401 的连接：清算结算是区块链与支付系统知识的交汇点——传统跨境清算靠代理行层层对账（见 [SYS4015](./SYS4015.md)），Amazon USP 用"统一结算平台 + 外部 vendor"的中心化方案解决多方分账（见 [SYS4018](./SYS4018.md)）。区块链提供第三条路：多方共享同一份账本、免对账。面试聊"区块链在支付领域的应用"时，能同时摆出这三条路，就是完整答案。

## 本章面试主线

> 协议 vs 实现（TCP/IP vs Web 类比）→ 共识可替换（PoW/PoS/DPOS，比特币选 PoW）→ 吞吐要分口径（公链实测 vs 联盟链理论）→ 链形态对应信任模型（公有/联盟/私有）→ 局限（监管、三角取舍）→ 落点（清算结算层，不是收单层）。
