## 1. 出国金融

出国金融不是单一 IT 系统，而是面向留学、旅游、商务等出境客群的一套零售金融产品体系，历史产品包括存款/资信证明、个人结售汇、境外汇款、留学汇、全球签、外币兑换等。中信公开材料将其概括为覆盖外币负债/理财、跨境结算、签证、资信证明、全球资产配置等。

``` text
                 出国金融
                    │
       ┌────────────┼────────────┐
       │            │            │
      C端           B端          M端
手机银行/小程序   合作机构      内部管理
       └────────────业务服务────┘
                    ↓
               银行后台系统
```

2018 年开始中信明显加强出国金融线上平台建设，手写笔记中的后续产品线包括存款证明、资产/资信证明、留学汇、交易流水证明、开户、全球签、外币兑换，渠道涉及手机银行、微信/小程序、内管、B 端合作方。

## 2. 留学汇

核心需求：留学生/家长向境外院校支付学费等费用。公开资料显示中信 2019 年正式推出跨境汇款"留学汇"。

相比普通境外汇款，更关注：

- 院校识别
- 收款对象可信性
- 外部院校数据
- 白名单
- 业务材料
- 合规校验
- 订单状态管理

## 3. 院校白名单：Problem

外部合作方提供院校数据，但不能不加处理直接成为银行内部可信主数据。会面对新增、重复、相似记录、修改、删除、待确认等情况。

历史笔记明确记录合作商维护白名单库、Mastercard 提供白名单接口，院校示例包括 Harvard / MIT / CalTech 等。

白名单可以降低：错误院校、重复院校、非法/异常收款对象、人工审核成本、数据质量问题。具体风险规则仍需原需求文档确认，不能自行扩大成 AML 风控系统。

``` text
合作商 / Mastercard
        ↓
     院校数据
        ↓
Import / Interface
        ↓
Validation / Dedup
        ↓
Review / Approval
        ↓
Internal Whitelist
        ↓
用户搜索 / 选择院校
```

## 4. 白名单设计与实现（本人 Ownership）

### 导入与状态

导入以操作和 `COLLEGE_ID` 等信息作为核心。导入结果统计包括：总数、新增、重复、待确认。

笔记记录的状态：**去重 / 不重 / 待确认**，"待确认"下还记录"到账、去重"。这里 OCR 语义可能不完整，后续若没有原图/需求文档，不应强行补全状态机。

### Component 设计

材料记录两类重要组件：

- **Verify Component**：负责相似数据查询、重复确认、关系获取。
- **Data Component**：负责 Add / Delete / Update。

此外存在两个外联方向：增删改组件、白名单去重查询/校验组件。

### 可恢复出的处理逻辑

``` text
             外部院校数据
                   ↓
               Import
                   ↓
             基础字段校验
                   ↓
           Verify Component
            /           \
      完全重复          不完全重复
         │                 │
       重复             相似匹配
                           ↓
                      人工/规则确认
                           ↓
         ┌───────────────┴─────────────┐
       新增                           待确认
         ↓
    Data Component
         ↓
     白名单数据库
```

其中"人工/规则确认"的精确实现仍需以后恢复，图用于帮助理解，不作为项目事实逐字背诵。

## 5. 为什么不是"只是 CRUD"

代码可以包含大量 CRUD，但业务问题是：

`External Master Data → Validation → Deduplication → Review → State Management → Trusted Internal Data → Customer Usage`

Senior 面试重点是数据接入、数据质量、状态、审核、用户侧与内管侧边界，而不是强行虚构高并发或分布式架构。

### 推荐讲述结构

- **Problem**：留学汇需要让用户选择境外院校，但院校数据来自外部合作方，存在新增、重复、相似记录、修改、删除、待确认。直接导入会导致主数据质量下降。
- **Constraint**：兼顾外部数据同步、内部审核、去重、用户搜索体验、数据一致性、权限。
- **Design**：外部白名单接入、批量导入、去重/相似查询、审核、增删改、状态管理、导入结果统计、内管权限。
- **Result**：目前没有可靠的量化指标，因此不编"审核效率提升 80%"、"覆盖全球 5 万所学校"、"准确率 99.9%"，除非未来找到证据。

## 6. 已确认能力

资料支持：

- 外部白名单接入；
- 批量导入；
- 增白审核；
- 去重审核；
- 删白审核；
- 查询；
- 增删改；
- 状态管理；
- 导入结果统计；
- 内管权限。

角色包括用户角色、行外用户、开放 B 端用户。具体权限矩阵若无原需求，不继续扩写。

## 7. 数据一致性

适合讲的是**业务数据一致性**：

- 同一院校是否重复；
- 外部更新与内部状态如何协调；
- 审核前后状态是否清晰；
- 修改/删除如何影响查询；
- 批量导入如何识别处理结果。

不要把它硬包装成分布式事务项目。跨系统同步的具体一致性实现必须以当时真实代码为准。

## 8. 审核与权限

``` text
External Data
   ↓
Internal Management
   ↓
Review / Approval
   ↓
Effective Whitelist
   ↓
Customer-facing Usage
```

可以讨论管理端/用户端边界、数据生效状态、审核和权限；没有证据时不要声称存在复杂 RBAC、工作流引擎或 AML 风控平台。

## 9. Scrum Master / Delivery

本人同期承担 Scrum Master / 敏捷交付相关工作，历史笔记有牵头迭代交付度统计、快速交付、敏捷转型和价值评估等记录。它作为工程协作补充，不抢走白名单设计开发的主线。

当时内部明确培训过 Scrum、SAFe、DevOps、精益、看板。Scrum 三个关键角色：PO（客户的唯一声音）、Scrum Master（促进团队、消除障碍、组织会议、推动敏捷）、Development Team（整体交付）。

``` text
需求澄清 → Product Backlog → 迭代计划/工作量估算
 → Sprint（看板 / Daily Standup / 开发测试）
 → Sprint Review → Retrospective
```

手写笔记明确出现"我牵头"：迭代交付度达到约 80%、每周统计各小组 IPD 上完成的迭代交付度、快速交付、敏捷转型、价值评估模型。因此面试中可以把 Scrum Master 讲成实际工作，而不是只说"主持站会"。

## 10. 本人 Ownership

**明确可说**：

> 留学汇院校白名单相关功能由我设计、开发。

可展开：需求理解、外部数据接入、批量导入、去重/相似查询、审核、增删改查、状态管理、内管能力。

## 11. 60 秒项目介绍

> 我在中信后半段参与出国金融的留学汇项目，其中院校白名单是我明确负责设计和开发的一块。院校基础数据由外部合作方提供，但不能直接导入，因为会有重复、相似记录、修改删除和待确认数据。我围绕这个问题做了白名单数据接入、批量导入、去重校验、审核、增删改查、状态管理和内管能力。这个项目不是算法系统，真正的难点是外部主数据进入银行内部后，如何保证数据质量、状态和业务流程一致。

## 12. 面试重点

为什么需要白名单；数据来源；外部数据为何不能直接导入；去重；审核；状态；批量导入失败；用户查询 vs 内管；本人具体设计什么；哪些细节不能乱说。

### 追问清单

1. 为什么要做院校白名单？
2. 白名单数据从哪来？
3. 如何判断重复院校？相似院校怎么处理？
4. 批量导入如何保证一致性？导入一半失败怎么办？
5. 删除院校时已有订单怎么办？
6. 外部合作方重复推送怎么办？
7. COLLEGE_ID 如何保证唯一？
8. 审核和数据操作如何分离？为什么 Verify 和 Data 分开？
9. 权限怎么控制？
10. 白名单更新过程中用户正在下单怎么办？
11. 如果数据量扩大 100 倍怎么办？

凡涉及具体实现而当前材料没有答案的，都应明确说"当年细节需要继续恢复"，不能临场编造。
