> **本章定位：**Blockchain Fundamentals。主线：**分布式账本 → 区块结构（链式哈希 + Merkle 树）→ 全网同步 → 确认后不可更改**。核心问题是"为什么全网共同记账能产生信任"；区块字段、节点类型属于支撑知识。

## 什么是区块链【P0】<img src="./icons/alibaba.gif" /><img src="./icons/sohu.gif" />

区块链相当于一本分布式的账本，全网中的每个节点共同参与维护这个账本。

每10分钟产生一个新区块，并同步更新到全网中的所有节点。全网确认后，就无法更改。

区块链技术可以用于例如维护全球统一的交易记录这种场景，未来可能应用到清算结算、股权交易、审计、公证等多个领域。

> **纠错说明：**"每10分钟产生一个新区块"是**比特币的出块参数**，不是区块链的固有属性——以太坊合并（The Merge）后约 12 秒一个 slot，联盟链可以配置到秒级。原面试材料把它写成了区块链通性。回答时应区分"某条链的参数"与"区块链机制本身"，主动指出这一点本身就是加分项。

### 中心化账本 vs 分布式账本【P0】

``` text
中心化账本（银行）：
所有交易 → 核心系统单点记账 → 账本唯一权威
信任来源：机构牌照、监管、对账制度
不一致 = 异常，靠 对账/冲正/日终核对 兜底

分布式账本（区块链）：
交易广播全网 → 每个全节点独立验证、独立记账
信任来源：协议规则 + 密码学 + 经济激励
一致性靠共识算法在互不信任的节点间达成
```

- 银行体系里，多方互不信任靠**对账**解决（见 [SYS4015 中信银行跨境电商](./SYS4015.md)）；区块链把同一类问题换了一个解法：让所有参与方持有同一份账本。
- 本质上是分布式系统的状态机复制（state machine replication）问题，但副本之间要容的不只是宕机，还有**作恶**（Byzantine fault，节点可能撒谎）。容错模型对比见 [SYS301 - Distributed Systems](./SYS301.md)。

> **Senior Java Focus：**一句话讲清区块链的价值主张：**把"信任某个机构"替换成"信任一套公开规则"**。支付/清算/结算系统（SYS401 金融章）全都在解决"多方互不信任怎么办"，区块链是这个问题的极端解法——这句框架话比背字段值钱。

## 区块与链的结构【P0】

``` text
┌──────────────────── Block N ────────────────────┐
│ Block Header                                    │
│   prevBlockHash   → 指向 Block N-1 的哈希        │
│   merkleRoot      → 本块全部交易的哈希汇总       │
│   timestamp / difficulty / nonce                │
├─────────────────────────────────────────────────┤
│ Block Body                                      │
│   Transactions: Tx1, Tx2, ..., TxM              │
└─────────────────────────────────────────────────┘

Block Hash = Hash(Block Header)
```

三个要点：

1. **Block Hash 只由 Block Header 决定**——交易数据通过 merkleRoot 间接参与。
2. **每个区块保留上一个区块的哈希**（prevBlockHash），块与块首尾相接形成链。改动任何历史数据，该块哈希立即改变，后续所有块的 prevBlockHash 全部失配，链条肉眼可见地断裂。
3. **链的"深度"就是安全性的来源**——越老的块后面压的块越多，改写成本越高（详见 [SYS4112 不可篡改机制](./SYS4112.md)）。

## Merkle 树【P1】

Block Body 里成百上千笔交易，如何用一个哈希代表全部？逐层两两哈希：

``` text
                 Merkle Root（进 Block Header）
                /            \
        Hash(AB)              Hash(CD)
        /      \              /      \
   Hash(A)   Hash(B)     Hash(C)   Hash(D)
     |         |           |         |
    Tx1       Tx2         Tx3       Tx4
```

价值：

- **整体校验**：任何一笔交易被改动，Merkle Root 立即变化，块哈希随之变化。
- **轻量证明（Merkle Proof）**：证明"Tx3 在这个块里"只需提供 Hash(CD)、Hash(AB) 两个中间哈希，O(log n) 而不是全部交易。轻节点（SPV）只下载区块头就能验证交易存在性。

## 节点角色【P1】

| 节点类型 | 保存内容 | 职责 |
|---|---|---|
| 全节点 | 完整账本（所有区块） | 独立验证每笔交易和每个区块，转发，不依赖任何人 |
| 矿工/验证者节点 | 完整账本 | 打包交易成候选块，参与出块竞争（PoW/PoS） |
| 轻节点（SPV） | 仅区块头 | 用 Merkle Proof 验证某笔交易是否上链 |

> **Senior Java Focus：**"独立验证"是去中心化安全的根基——全节点不信任矿工给的块，自己按规则验。类比支付系统：上游清算文件不能直接信，要自己做校验（USP 的 Deposit Check / RF Check，见 [SYS4018 Amazon USP](./SYS4018.md)）。

## 出块、同步与确认【P0】

一笔交易的完整生命周期：

``` text
用户签名交易
   ↓ 广播
全网节点各自验证（签名、余额/双花规则）
   ↓ 进入待打包池（mempool）
矿工打包进候选块 → 出块（全网同步新块）
   ↓
后续新区块不断叠加 = 确认数增长
   ↓
确认数足够 → 交易在经济上不可逆
```

- **出块间隔是参数，不是机制**：比特币约 10 分钟，以太坊合并后约 12 秒，联盟链可到秒级。
- **确认数**：交易被包含进最新块算 1 次确认，之后每新增一个块加 1 次。比特币惯例是 **6 次确认**后视为不可逆。
- **最终性（finality）**：PoW 链的"不可逆"是概率性的（被更长链推翻的概率随深度指数衰减）；PBFT 类共识给出的是**确定性最终性**（一旦提交永不可逆）。这是区分公链与联盟链的关键维度，详见 [SYS4113 共识算法](./SYS4113.md)。

## 应用领域【P1】

区块链未来可能应用到清算结算、股权交易、审计、公证等多个领域。

展开讲为什么恰好是这些领域——它们的共同点是**多方互不信任 + 都要同一份记录**：

- **清算结算**：跨境清算涉及多家互不信任的机构，现状是层层代理行 + 对账；共享账本是天然候选（呼应 [SYS4015](./SYS4015.md)、[SYS4018](./SYS4018.md) 的清算结算知识）。
- **股权交易**：登记、过户、清算本来就要多方对同一份股东名册达成一致。
- **审计**：不可篡改的 append-only 日志本身就是审计证据链。
- **公证**：把文件哈希上链即可证明"某时刻该文件存在且未被修改"（存在证明），不需要公开文件内容。

## 本章面试主线

> 分布式账本（人人一份、共识保证一致）→ 区块结构（Header 链式哈希 + Merkle 汇总交易）→ 出块与确认（深度即安全）→ 价值主张（信任机构 → 信任规则）。
