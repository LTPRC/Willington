## 1. Java Execution Model

### Source Code → Bytecode → JVM

```
┌──────────────┐  javac   ┌────────────────┐         ┌─────────────┐  对应平台的机器码   ┌──────────────────────┐
│ Java 源程序   │ ───────> │ 字节码 .class   │ ──────> │    JVM       │ ────────────────>  │ Windows / macOS /    │
│   (.java)    │   编译   │  （平台无关）    │         │ （与平台绑定） │    解释执行 + JIT    │ Linux 操作系统        │
└──────────────┘          └────────────────┘         └─────────────┘                    └──────────────────────┘
```

我们编写的 Java 源码，编译后生成 `.class` 字节码文件；字节码由 JVM 加载，在执行时翻译（解释执行 + JIT 编译）为特定机器上的机器码。编写的 Java 程序本身不做任何改变，仅通过 JVM 这一"中间层"即可在不同平台上运行，即 "Write once, run anywhere"。

JVM 执行期的主要职责（加载类、创建执行线程并分配线程私有区域、执行期间管理内存空间）属于 JVM 课程范畴。

> See: CSE301

### Platform Independence<img src="./icons/gupao.gif" /><img src="./icons/tuling.gif" />

*核心优势*

跨平台的是 **Java 程序（字节码）**，而不是 JVM。JVM 本身是用 C/C++ 开发的本地程序，是编译后的机器码，**不能跨平台**——不同平台需要安装各自版本的 JVM。

跨平台能力由两级"翻译"保证：

- 编译期：`源程序 → 字节码` 是平台无关的，同一 `.class` 文件可以分发到任何平台；
- 运行期：`字节码 → 机器码` 由各个平台上的 JVM 实现完成，平台差异由 JVM 屏蔽。

### JDK / JRE / JVM 基本关系

| 组成 | 内容 | 说明 |
| ---- | ---- | ---- |
| JVM  | 字节码执行引擎 | 见 CSE301 |
| JRE  | JVM + 核心类库 | 运行环境。Java 9 模块化之后不再单独分发 JRE，可用 `jlink` 按需裁剪运行时 |
| JDK  | JRE + 开发工具（javac、jdb、javadoc 等） | 开发所需 |

## 2. Java Type System

### Primitive Types<img src="./icons/citic.gif" /><img src="./icons/baidu.gif" /><img src="./icons/luban.gif" /><img src="./icons/mashibing.gif" /><img src="./icons/bytedance.gif" /><img src="./icons/pingan.gif" />

| 类型    | 位宽 | 范围                                          | 默认值  | 备注                                       |
| ------- | ---- | --------------------------------------------- | ------- | ------------------------------------------ |
| byte    | 8    | -128 ~ 127（-2^7 ~ 2^7-1）                    | 0       | 二进制补码表示；用于大型数组节约空间       |
| short   | 16   | -2^15 ~ 2^15-1                                | 0       |                                            |
| int     | 32   | -2^31 ~ 2^31-1                                | 0       | 整型字面量的默认类型                       |
| long    | 64   | -2^63 ~ 2^63-1                                | 0L      | 字面量加 `L`；建议大写，避免与数字 `1` 混淆 |
| float   | 32   | IEEE 754 单精度                               | 0.0f    | 字面量加 `F`/`f`                           |
| double  | 64   | IEEE 754 双精度                               | 0.0d    | 浮点字面量的默认类型                       |
| boolean | —    | true / false                                  | false   | 仅表示逻辑值；实际存储宽度由 JVM 实现决定，见 CSE301 |
| char    | 16   | `\u0000` ~ `\uffff`（0 ~ 65,535）             | `\u0000` | UTF-16 code unit，不一定是"一个字符"，见 §12 |

字面量参考：

```java
int dec = 26;          // 十进制
int hex = 0x1a;        // 十六进制
int bin = 0b11010;     // 二进制（Java 7+）
long l = 100000L;
float f = 234.5f;
double d = 123.4;
int million = 1_000_000;  // 数字下划线分隔（Java 7+），仅增强可读性
```

### Reference Types

除 8 种 primitive 之外，所有类型均为引用类型：class、interface、array、enum、annotation 等。引用类型的变量保存的是**对象引用（reference）**——可理解为受限制的指针：没有指针运算、不能转换为整数、只能通过引用访问对象。

### Primitive vs Reference

| 维度     | Primitive                     | Reference                          |
| -------- | ----------------------------- | ---------------------------------- |
| 存储内容 | 直接保存数值本身              | 保存对象引用，对象本身在堆上       |
| null     | 不允许                        | 可以为 `null`                      |
| 赋值     | 拷贝数值                      | 拷贝引用（两个变量指向同一对象）   |
| `==`     | 比较值是否相等                | 比较是否指向同一对象（非 equals）  |
| 默认初始 | 0 / 0.0 / false / '\u0000'    | `null`                             |

> JVM 中对象的具体内存布局（对象头、字段对齐等）见 CSE301，本文不讨论。

## 3. Numeric Semantics

### Integer Representation

- Java 整数类型（byte/short/int/long）均以**二进制补码（two's complement）**表示，因此最小值是 -2^(n-1) 而最大值是 2^(n-1)-1。
- **溢出不回抛异常，而是回绕**：`Integer.MAX_VALUE + 1 == Integer.MIN_VALUE`。这是 Java 整数运算的明确语义，也是工程与面试中的高频考点。需要防溢出时使用 `Math.addExact` / `Math.multiplyExact`（溢出抛 ArithmeticException）。
- 运算中的类型提升：低精度自动向高精度转换（`byte → short → int → long → float → double`）；高精度赋给低精度必须显式强转，可能丢精度或溢出。

原码/反码/补码的对照推导见 Appendix F。

### Floating Point<img src="./icons/luban.gif" /><img src="./icons/mashibing.gif" />

- float / double 遵循 **IEEE 754**，内部用符号位 + 指数 + 尾数的二进制科学计数法表示。
- **二进制无法精确表示 0.1**：十进制 0.1 转换为二进制是 `0.0001100110011...`（1100 无限循环），float/double 只能截断存储，因此是近似值。

```java
System.out.println(3 * 0.1 == 0.3);   // false：浮点数不能完全精确地表示
```

- 结论：**浮点数不能用来表示货币等需要精确十进制小数的值**，此类场景使用 `BigDecimal`（见下）或分单位的整型 long。
- 取整：

```java
Math.round(-1.5);  // 返回 -1。原理：参数加 0.5 后向下取整，即 (int)Math.floor(a + 0.5)
```

### BigDecimal<img src="./icons/mashibing.gif" />

BigDecimal 可以表示**任意精度的十进制小数**，是财务/金额计算的标准选择。float/double 的浮点值是近似值，二者不适合作为价格的数据类型。

**构造方式的三者差异——重点：**

```java
new BigDecimal("0.1");   // 精确等于 0.1。String 构造，直接记录十进制小数，推荐
BigDecimal.valueOf(0.1); // 精确等于 0.1。内部走 Double.toString(0.1) => "0.1"，等价于上一行，推荐
new BigDecimal(0.1);     // 不等于 0.1！存储的是 0.1 的完整二进制展开（52+位尾数），应避免使用
```

**比较：**

- `equals` 同时比较 **value 和 scale**，所以 `new BigDecimal("1.0").equals(new BigDecimal("1.00"))` 为 `false`。
- 比较数值大小一律用 `compareTo`（返回 -1/0/1）。
- 作为 Hash key 时，`1.0` 和 `1.00` 会被当作不同的 key。可改用 `TreeSet`/`TreeMap`，或先 `stripTrailingZeros()` 归一化。

**计算：**

- 除法、设置小数位必须**显式指定 rounding**，否则遇到无限循环小数直接抛 `ArithmeticException`：

```java
BigDecimal fee = amount.multiply(rate).setScale(2, RoundingMode.HALF_UP);
BigDecimal avg = total.divide(count, 2, RoundingMode.HALF_UP);
```

- 工程实践：金额优先用分/最小单位的 `long`；必须用 BigDecimal 时，从 String 或 `valueOf(double)` 进入，全程显式 scale + rounding，序列化输出前统一 scale。

## 4. Wrapper Types<img src="./icons/luban.gif" />

Java 为每个 primitive 提供了对应的包装类型，使其可以作为对象操作。从 **Java 5** 开始引入自动装箱/拆箱（auto-boxing/unboxing），二者可以隐式转换。

| Primitive | Wrapper   |
| --------- | --------- |
| boolean   | Boolean   |
| char      | Character |
| byte      | Byte      |
| short     | Short     |
| int       | Integer   |
| long      | Long      |
| float     | Float     |
| double    | Double    |

主要用途：

1. **泛型参数必须是引用类型**：`List<Integer>` 合法，`List<int>` 编译错误。
2. **与 String 互转**：

```java
int num  = Integer.parseInt("12");    // 解析为基本类型
Integer num2 = Integer.valueOf("12"); // 返回包装对象
double d = Double.parseDouble("12.2");
String s1 = String.valueOf(1234);     // 任意类型 -> String
String s2 = 12 + "";                  // 同上
String s3 = new Double(2.3).toString();
```

3. 集合容器：HashMap/HashSet 等对包装类型按值语义参与 equals/hashCode（对象相等契约见 §5）。

### Integer Cache<img src="./icons/mashibing.gif" />

给 Integer 赋 int 字面量时编译器调用 `Integer.valueOf`。IntegerCache 默认缓存 **-128 ~ 127** 的对象（上限可通过 `-XX:AutoBoxCacheMax` 调整），范围内直接复用缓存对象，范围外每次 new：

```java
Integer f1 = 100, f2 = 100, f3 = 150, f4 = 150;
System.out.println(f1 == f2); // 输出 true（100 在缓存范围内，同一对象）
System.out.println(f3 == f4); // 输出 false（150 超出缓存，两个不同对象）
```

### == vs equals

- 包装类型之间比较**不要用 `==`**：`==` 比较的是引用是否相同，结果取决于缓存范围（见上）。
- 比较两个包装对象的数值相等用 `equals`，或与基本类型比较触发拆箱：

```java
Integer a = 100, b = 100;
a.equals(b);  // true
a == 100;     // true（与 int 比较时拆箱，比较值）
```

### Null Unboxing

拆箱对 `null` 直接抛 NullPointerException：

```java
Integer x = null;
int y = x;      // 自动拆箱 -> NullPointerException
if (x == 1) {}  // 同样拆箱，x 为 null 时抛 NullPointerException
```

从数据库/远程调用读入包装类型后参与算术或比较前，必须先判空。

### Primitive vs Wrapper<img src="./icons/mashibing.gif" />

以整型为例，Integer 对象比 int 占用更多内存——对象需要存储元数据（对象头等），int 仅是原始数据。具体对象布局与占用见 CSE301。工程上：POJO 字段优先基本类型，仅在泛型、缓存/序列化框架要求、或需要表达"无值"（null）时使用包装类型。

## 5. equals / hashCode Contract<img src="./icons/citic.gif" />

对象相等语义是 HashMap / HashSet 等哈希容器的地基。HashMap 的内部机制（哈希扰动、扩容、树化、线程不安全）见 CSE2742；并发容器见 CSE3117。

### Object 默认实现

不重写时，`Object` 的两个方法都是**身份（identity）语义**：

- `equals`：等价于 `==`，判断是否为同一个对象；
- `hashCode`：返回基于对象身份的哈希值，与对象内容无关。

因此两个字段完全相同的对象，默认 `equals` 为 `false`、`hashCode` 通常不同——不能按"值相等"作为容器 Key 使用。

### 契约内容

`equals` 必须满足：

- 自反：`x.equals(x)` 恒为 `true`；
- 对称：`x.equals(y)` 与 `y.equals(x)` 结果一致；
- 传递：`x.equals(y)` 且 `y.equals(z)` ⇒ `x.equals(z)`；
- 一致：参与比较的状态未变时，多次调用结果不变；
- 与 `null` 比较：`x.equals(null)` 恒为 `false`，不抛 NullPointerException。

`equals` 与 `hashCode` 的关系是**单向约束**：

```
equals 为 true  ⇒  hashCode 必须相同
hashCode 相同    ⇏  equals 一定为 true（允许哈希碰撞）
```

### 为什么重写 equals 必须重写 hashCode

哈希容器的查找分两步：**先用 hashCode 定位候选桶（bucket），再在桶内用 equals 确认**——hashCode 负责缩小候选范围，equals 负责确认逻辑相等。

若两个逻辑相等的对象 `equals` 为 `true` 但 `hashCode` 不同，会被散到不同的桶：`get` 找不到、`put` 存出"重复"Key、HashSet 去重失效。所以规则是：**重写 equals 必须一并重写 hashCode，且相等对象必须得到相同的哈希值。**

### 哈希碰撞是正常现象："Aa" 与 "BB"<img src="./icons/citic.gif" />

String 的哈希算法为 `h = 31 * h + 当前字符`：

```
"Aa" = 31 * 65('A') + 97('a') = 2112
"BB" = 31 * 66('B') + 66('B') = 2112
```

所以 `"Aa".hashCode() == "BB".hashCode()` 为 `true`，而 `"Aa".equals("BB")` 为 `false`。这道题考的不是背出 2112，而是两点：碰撞是正常现象；hashCode 相同不能替代 equals——HashMap 定位到桶后必须继续用 equals 判断。

### 工程实践

- 实现用 `Objects.equals` / `Objects.hash`，或交由 IDE / Lombok 生成，不要手写易错组合。
- 参与 hashCode 计算的字段应不可变：字段一改，对象在 HashMap 中就会"找不到自己"；String、Integer 等不可变类型是最常用的 Key。

> 面试口径：hashCode 把对象映射为 int，帮助哈希容器快速缩小查找范围，允许碰撞，不是唯一 ID；两个对象 equals 为 true 则 hashCode 必须相同，反之不成立。重写 equals 必须一并重写 hashCode，否则逻辑相等的 Key 会落入不同桶，HashMap / HashSet 语义被破坏。

## 6. Operators & Expressions

只保留容易出错、仍有理解价值的内容；完整运算符清单与优先级表见 Appendix D。

### Arithmetic<img src="./icons/netease.gif" /><img src="./icons/mashibing.gif" />

```
+, -, *, /, %, ++, --
```

- `++i` 与 `i++` 都使 `i` 加 1，但表达式的值不同：`++i` 自增后的值，`i++` 自增前的值；`--` 同理。
- `++`/`--` **不是线程安全的原子操作**（读取 → 修改 → 写回多个步骤，多线程交错会丢更新）。原子更新见 CSE311。

### Compound Assignment<img src="./icons/luban.gif" /><img src="./icons/mashibing.gif" />

```
=, +=, -=, *=, /=, ...
```

`a += b` 隐含一次强制类型转换，等价于 `a = (T)(a + b)`（T 为 a 的类型）：

```java
byte b = 1;
b += 1;     // 编译通过，隐式强转回 byte
b = b + 1;  // 编译错误：int 不能隐式转回 byte
```

### Logical

```
&&, ||, !    （短路）
&,  |        （不短路；对 boolean 是逻辑运算，对整数是位运算）
```

`&&`/`||` 短路求值：左侧已能决定结果时右侧不执行，常用于前置判空。

### Bitwise & Shift

```
&, |, ^, ~, <<, >>, >>>
```

- `&` `|` `^` `~`：按位与/或/异或/取反，仅作用于整数类型。
- `<<`：左移，低位补 0。移位前 byte/short/char 会先提升为 int。
- `>>`：**arithmetic right shift（算术右移）**，高位**补符号位**，负数右移仍为负。
- `>>>`：**logical right shift（逻辑/无符号右移）**，高位**补 0**，结果按无符号数解释。

```java
-8 >> 1;   // -4：符号位补 1
-8 >>> 1;  // 2147483644：高位补 0
```

注意：移位位数会按 32（int）/ 64（long）取模，如 `1 << 33` 等价于 `1 << 1`。

## 7. Java Parameter Passing<img src="./icons/kingdee.gif" />

**Java is always pass-by-value.** 不存在引用传递（pass-by-reference）：调用方法时，每个实参都会复制一份值传给形参。

### Primitive Value

传递的是数值的**副本**，方法内修改形参不影响调用方：

```java
static void increment(int i) {
    i++;  // 只改了副本
}
int a = 0;
increment(a);
System.out.println(a);  // 0
```

### Reference Value

对象变量中保存的是 reference。**传递的是 reference value 的副本**——副本与调用方变量指向同一个对象：

```
caller reference ──────┐
                       ▼
                   ┌──────────┐
method parameter ─▶│  object  │   两个引用指向同一对象
                   └──────────┘
```

因此：

- 方法内部**修改对象状态**（通过副本调用 setter、修改字段）：调用方**可以观察到**变化——因为改的是同一个对象。
- 方法内部**给形参重新赋值**（让它指向另一个对象）：**不会**改变调用方变量的引用指向。

```java
class User { String name; User(String n) { this.name = n; } }

static void modify(User u) {
    u.name = "B";               // 修改同一个对象 -> caller 可见
}
static void reassign(User u) {
    u = new User("C");          // 只改了引用副本的指向 -> caller 不可见
}

User u = new User("A");
modify(u);
System.out.println(u.name);  // B
reassign(u);
System.out.println(u.name);  // 仍是 B
```

常见误判来源：把"可以通过引用副本修改共享对象"误当作引用传递。判断标准只有一个——**有没有可能改变调用方变量本身保存的值**（primitive 值 / 引用指向），Java 中答案永远是否定的。

## 8. Access Control<img src="./icons/tr.gif" /><img src="./icons/ericsson.gif" />

| 修饰符            | 当前类 | 同包 | 子类 | 其他包 |
| ----------------- | ------ | ---- | ---- | ------ |
| `public`          | √      | √    | √    | √      |
| `protected`       | √      | √    | √*   | ×      |
| package-private（默认，无修饰符） | √ | √ | × | × |
| `private`         | √      | ×    | ×    | ×      |

\* protected 对子类开放的是**继承访问权**：跨包子类可以访问自己继承来的 protected 成员，但不能通过其他包中父类/兄弟类的实例直接访问其 protected 成员。

补充：一个 `.java` 源文件中最多只能有一个 `public` 顶层类（文件名须与其一致）；包私有是封装的默认手段，公有 API 设计时应尽可能收窄可见性。

## 9. Core Modifiers

### static<img src="./icons/luban.gif" />

static 表示成员属于**类本身**而非某个实例，随类加载而存在，不依赖 `this`。

```java
static int num;                                  // 静态变量：全类共享一份
public static void main(String[] args) {}        // 静态方法：不能访问实例成员
static { int num = 0; }                          // 静态块：类加载时执行，多用于静态资源初始化
public static class StaticInnerClass { ... }     // 静态嵌套类：不持有外部类实例引用
```

类加载与初始化顺序细节见 CSE301。static import 见 Appendix C。

### final<img src="./icons/alibaba.gif" /><img src="./icons/luban.gif" />

#### final variable

包括成员变量和局部变量：只能被赋值一次。成员变量必须在声明时或构造方法中赋值。

#### final reference

引用一旦被赋值就不能再指向其他对象，但**所指对象内部的状态仍然可以改变**——final reference ≠ immutable object（见 §10）。final 方法参数表示生存期内不能重新赋值（对引用参数而言只是不能换指向）。

#### final method

表示该方法**不能被 override**，但可以被继承。

> 注意：现代 JVM（HotSpot）的内联（inline）决策由运行时 profiling 动态做出，与 `final` 关键字无因果关系。不要把 final 当作性能优化手段，它只是语义约束。

#### final class

表示该类**不能被继承**（如 String、Integer）。final class 的方法隐式为 final。

final 不可修饰构造方法（构造器本来就不参与继承与重写）。

## 10. Immutability<img src="./icons/mashibing.gif" />

### Immutable Object

对象构造完成之后，其对外可见的状态永远不会改变。任何"修改"操作都返回一个新对象。典型例子：String、Integer 等包装类、java.time 中的类。

### final Reference vs Immutable Object

两个相互独立的维度，经常混淆：

- `final` 是**引用维度的约束**：变量不能换指向，但对象内容仍可变。
- Immutable 是**对象维度的约束**：对象内容不可变，与持有它的变量是否 final 无关。

### How to Design an Immutable Class

不可变类在对象构造完成之后，内部状态不会被改变。设计要点：

- Class 定义成 `final`，避免被继承（或所有构造器私有 + 静态工厂，防子类破坏）。
- 所有成员变量声明为 `private final`。
- 不提供任何改变状态的方法；getter 不要把内部成员引用直接暴露给外部客户端，需要访问时**返回成员的 copy**。
- 可以包含可变对象作为成员，但**不要共享可变对象的引用**：不要接受/返回内部可变组件的直接引用，必要时返回其拷贝。最常见的例子是对象中包含一个 Date 引用——防御性拷贝（defensive copy）的场景。
- 构造期间注意不要让 `this` 逸出（不要在构造器中发布 this 或启动线程）。

### Defensive Copy

```java
public final class Period {
    private final Date start;
    private final Date end;

    public Period(Date start, Date end) {
        this.start = new Date(start.getTime());  // 防御性拷贝：不信任外部传入的引用
        this.end   = new Date(end.getTime());
    }
    public Date start() { return new Date(start.getTime()); }  // 返回拷贝，防内部状态外泄
    public Date end()   { return new Date(end.getTime()); }
}
```

注意防御性拷贝必须针对**可变成员**；对不可变成员（String、其他 immutable 类）无需拷贝。

### Why Immutability Helps Concurrency

状态不可变 ⇒ 多个线程同时读取同一对象不需要任何同步，天然线程安全；也不会有读写交错导致的不一致。这是函数式风格与 Modern Java Stream 大量依赖不可变对象的原因。

> 同步、happens-before、原子性等并发细节见 CSE311。

## 11. Enum

### enum VS Enum<img src="./icons/citic.gif" />

`enum` 是关键字；`java.lang.Enum` 是所有枚举类型的隐式父类：

```java
public abstract class Enum<E extends Enum<E>>
        extends Object implements Comparable<E>, Serializable
```

使用 `enum` 定义的枚举类本质上相当于一个继承了 `Enum` 的 final class，每个枚举常量是该类的**单例实例**。

### 为什么用 enum 而不是 int/String 常量

- **类型安全**：编译期检查，不可能传入定义之外的值；int 常量做不到。
- 每个常量是单例，可用 `==` 直接比较。
- 本质是类，可带字段和方法（构造器私有）、实现接口。
- 适合表示**有限状态集合**（订单状态、方向、级别等），与 `switch` 配合良好。

复杂用法（EnumMap、EnumSet、valueOf 容错）按普通类使用即可，不展开。

## 12. Character & Encoding<img src="./icons/mashibing.gif" />

### Unicode

Unicode 是一个**字符编码标准/字符集合体系**：为世界上每个字符分配唯一的**码位**，覆盖范围 U+0000 ~ U+10FFFF。**Unicode 不等于"每个字符 2 字节"**——它只规定码位与字符的对应关系，存储成字节时用哪种 UTF 编码（UTF-8/UTF-16/UTF-32）决定每个字符占几个字节。

### Code Point

码位（code point）是一个字符的数值编号，范围 0 ~ 0x10FFFF（共 1114112 个位置），其中 BMP（Basic Multilingual Plane，U+0000 ~ U+FFFF）之外的称为补充字符（supplementary characters），例如部分 CJK 扩展汉字和 emoji。

### UTF-8

变长编码：每个字符 1~4 字节。ASCII 字符只占 1 字节且与 ASCII 完全兼容；中文通常 3 字节。是网络传输与文件存储的主流编码。

### UTF-16

由 **16-bit code unit** 组成：BMP 内字符用 1 个 code unit；补充字符用 2 个 code unit 组成的 **surrogate pair**（代理对，范围 U+D800 ~ U+DFFF）表示。

### Java char

**Java char 是一个 16-bit 的 UTF-16 code unit，不是一个"Unicode 字符"。**

- 对 BMP 内的字符（含大部分中文），一个 char 恰好对应一个字符；
- 对补充字符（如部分 emoji），一个 code point 需要**两个 char**（surrogate pair）表示。

由此产生的 API 语义差异：

```java
String s = "😀";            // 补充字符：1 个 code point
s.length();              // 2：返回的是 UTF-16 code unit 数，不是字符数
s.codePointCount(0, s.length());  // 1：真正的字符（code point）数
s.charAt(0);             // 取到的是半个 surrogate pair，不是完整字符
// 遍历应按 code point：
s.codePoints().forEach(cp -> ...);            // Java 8+（Modern Java）
```

### String

String 本质是 UTF-16 code unit 序列。与编码相关的必要语义仅此一层；String 的内部实现及其在 Java 版本间的差异（compact strings 等）属于 JVM/实现层，后续章节另行处理。

## 13. Language Basics Reference

### instanceof<img src="./icons/luban.gif" />

`instanceof` 是双目运算符，测试一个对象是否为指定类型的实例（或其子类型实例）：

```java
boolean result = obj instanceof String;
```

- `null instanceof 任意类型` 恒为 `false`，不会抛 NPE。
- 运行期类型判断，是多态实现与防御性编码的基础手段；Modern Java 的模式匹配（`instanceof` + binding）后续章节处理。

### Basic switch<img src="./icons/kaikeba.gif" /><img src="./icons/mashibing.gif" /><img src="./icons/bytedance.gif" />

传统 `switch(expr)` 的合法类型演进：

- Java 5 之前：`byte`、`short`、`char`、`int`（及其包装类）。
- Java 5 起：可作用于 `enum`。
- Java 7 起：可作用于 `String`。
- `long`（以及 boolean、float、double）在所有版本中都不可以。

语义要点：按值匹配 `case`，匹配后**顺序执行直到遇到 `break`**（case fall-through），`default` 可选；浮点与 boolean 被排除正是因为不适合离散等值比较。

> switch expression、箭头语法、pattern matching（Java 14+/17+）属 Modern Java 演进，后续章节处理。

## F. Low-Priority Fundamentals

### Java 相对 C++ 的取舍<img src="./icons/mashibing.gif" />

Java 早期设计语言时取消了以下 C/C++ 设定：

- `#include`、`#define` 等预处理功能
- `struct`、`union`、`typedef`
- 脱离于类之外的函数
- 指针（内存直接访问与运算）
- 多重继承（类）
- `goto`（关键字仍被保留）
- 操作符重载
- 全局变量
- 手动内存管理

### 安全机制

- 取消指针，防止任意访问其他内存区域，配合数组边界检查避免越界访问。
- 自动内存管理（垃圾回收），防止垃圾处理不当造成内存溢出。
- 字节码在传输过程中使用公开密钥加密机制（PKC）。
- 运行环境提供四级安全性保障：字节码校验器、类装载器、运行时内存布局、文件访问限制。

### 健壮性

强制类型机制、异常处理、垃圾回收、安全检查等机制保障 Java 的健壮性。

### 原码、反码、补码<img src="./icons/mashibing.gif" />

补码（two's complement）的推导过程。现代理解只需记住"补码 = 反码 + 1，最小值多一个"的结论，推导留档备查：

|                 | 原码 | 反码                     | 补码   |
| --------------- | ---- | ------------------------ | ------ |
| 大于等于0的整数 | 自身 | -                        | -      |
| 小于0的整数     | 自身 | 原码除符号位以外全部取反 | 反码+1 |

### boolean 的 JVM 表示<img src="./icons/bbbbzxlb.gif" />

语言层面 boolean 只有 true/false 两个逻辑值，**不规定任何字节宽度**。

- Oracle HotSpot 中 boolean 数组按 byte 数组编码，每个元素 1 字节；
- 标量 boolean 在运算时以 int 形式处理（4 字节）。

以上均为具体 JVM 的实现细节而非 Java 语言保证，其他 JVM 可能不同。精确的对象/数组内存占用见 CSE301 Object Layout。
